# FríoTrack Landing 0.1.0

Primera versión etiquetada de la landing, con correcciones de integración hacia la SPA y de los estados del formulario de contacto.

## Cambios observables

El inicio de sesión permite elegir Coordinador Logístico o Cliente de Carga y abre la ruta `/#/login?role=…&lang=…` de la aplicación. El registro lleva a `/#/register?role=cargo-client&lang=…`. La landing no solicita contraseñas; las credenciales y los permisos se validan en la API de la aplicación. El idioma elegido en la URL tiene prioridad sobre el guardado y el navegador.

El formulario de contacto indica que es una demostración mientras `contactEndpoint` sea `null`. En ese modo no envía ni persiste datos y no promete una respuesta comercial. Al configurar un receptor, solo una respuesta HTTP satisfactoria muestra confirmación. Los errores de red y de HTTP conservan los campos y permiten reintentar.

## Validación

- Sintaxis JavaScript comprobada con `node --check` en todos los archivos de `assets/js/` e `i18n/`.
- Los diccionarios español e inglés conservan el mismo conjunto de claves.
- Se comprobaron 88 referencias locales de HTML, imágenes, scripts y fragmentos sin enlaces rotos. Las fotografías no disponibles se sustituyen por las iniciales junto al nombre completo de cada integrante.
- La validación en Chrome comprobó español e inglés a 1440 y 390 px: prioridad del idioma de URL, ausencia de desbordamiento horizontal, claves traducibles presentes, ausencia de formulario local de contraseñas, URLs de acceso por ambos perfiles y registro de cliente, cierre del selector con Escape, demostración de contacto y reinicio, y ancla localizada de términos.
- Con un receptor de prueba interceptado, HTTP 500 y un error de red conservaron los datos y mostraron error; HTTP 200 mostró confirmación. Las tres solicitudes se interceptaron localmente y no se enviaron datos a un servicio externo.

El [recibo de validación](../evidence/review-corrections-2026-11-10.json) registra el alcance y las limitaciones. Estas comprobaciones funcionales no equivalen a una revisión completa de accesibilidad ni a validar un receptor comercial desplegado.

## Alcance de publicación

La release registra el código revisado. El destino de TB1 sigue siendo [Azure Static Website](https://friotracktb1bce6db1b.z22.web.core.windows.net/landing/); publicar una release no despliega sus cambios allí. Se debe conservar la SPA en la raíz al actualizar `/landing/`.

La recepción comercial real, los sensores físicos, los pagos y una auditoría completa de accesibilidad permanecen fuera de este sitio estático. Los precios son referenciales y el panel usa datos simulados.
